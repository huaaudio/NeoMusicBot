# NeoMusicBot 首次审查记录（2026-09-21）

本文保留首次审查时的版本和状态，后续进度见[现代化审查记录](modernization-audit.md)。

## 当前做到哪里

这是一个给 Discord 语音频道播放音乐的 bot，Bilibili 是音源之一，并非 B 站直播间聊天机器人。
当前工作区已从早期 B 站补丁扩展为 Java 25、JDA 6、JDAVE 和 Slash 命令版本。
这些主体改动在本次审查开始前已经存在，大部分仍未提交；最后一个提交是 `45c256e`（`init commit for bili`）。

| 部分 | 当前实现 |
| --- | --- |
| Bilibili | HTTPS 视频链接、b23 短链接、BV/av 编号、指定分 P；每次加入一个分 P |
| 解析与播放 | yt-dlp 解析；队列保存稳定编号；播放时解析/刷新临时音频地址；失效流有限重试 |
| 其他音源 | YouTube 主解析与 yt-dlp 后备、SoundCloud、Discord 附件 |
| 控制 | Slash 点歌、队列、暂停/恢复、跳转进度、跳过、循环、音量、DJ 权限 |
| 歌单与配置 | 本地歌单、默认播放列表、服务器设置写入及备份 |
| 语音 | JDA/JDAVE、频道预留、断线状态处理、无人时离开 |
| 发布 | Maven Wrapper、两平台构建、许可证、SBOM、媒体探测及草稿发布工作流 |

B 站关键词搜索、整份收藏夹/合集导入尚未实现。`/search` 和文字点歌的默认搜索仍是 YouTube。
旧的前缀命令已被 Slash 命令取代。

## 本次修复

1. **播放结束可能死锁。** Lavaplayer 在持有 `trackSwitchLock` 时通知歌曲结束，旧代码同步等待服务器队列线程；队列线程开始下一首又要获得同一把锁。外部播放器事件改为异步进入队列；已经在队列线程的事件继续直接处理。同步修复停止后延迟到达的结束事件重新触发单曲循环的问题。
2. **B 站短链接可能丢失分 P。** 从 yt-dlp 的 `_pN` 编号和最终网页 URL 恢复分 P，检查与请求是否一致；稀疏或乱序结果缺少指定分 P 时，不再按数组位置误选另一 P。
3. **链接重复编码。** 已编码的 `%32`、`%2F` 等不再变成 `%2532`、`%252F`，读取参数时按 UTF-8 解码。
4. **歌单完成状态错误。** 搜索结果或带选中曲目的歌单原先会调用两次完成回调；空搜索结果会访问第一个不存在的元素；空本地歌单不会回调。现已统一处理。默认歌单的 requester metadata 也改为当前播放器使用的 `RequestMetadata.EMPTY`。
5. **Windows 构建入口报错。** 普通 Maven 用户目录的 `Target` 属性可为 null，旧 Wrapper 直接索引 `[0]` 会失败；现已处理没有链接目标的目录。
6. **更新提醒误报。** 定时提醒改用已有语义版本比较，避免把较旧版本或仅带 `v` 前缀的相同版本当成更新。
7. **发布校验文件路径错误。** 最终 `SHA256SUMS` 改为相对发布文件所在目录生成，避免要求下载者另外建立 `dist/` 目录。

## 验证

- 新增回归用例先在旧实现上复现了分 P、编码、重复回调和空歌单错误。
- 使用真实 Lavaplayer 播放器验证自然结束时切换下一首，另测停止与单曲循环的并发事件。
- 匿名实测 `BV13x41117TL`：解析成功，并实际取得 10 个音频帧。
- 匿名实测 `BV1bK411W797?p=2`：保存的稳定编号为 `bilibili:BV1bK411W797:2`，并实际取得 10 个音频帧。
- 实测使用工作区已有的 yt-dlp 2026.07.04 和 Deno 2.9.3，不使用登录 Cookie；不保存签名音频地址。
- Windows 测试环境的系统临时目录存在访问限制，测试时将当前进程的 `TEMP` 和 `TMP` 指向工作区 `target/audit-tmp`。这解决了临时目录清理和原生 DLL 加载的环境错误。

Windows `mvnw.cmd --batch-mode --no-transfer-progress -Pnative-windows-x86-64 verify`
已通过：共 122 个测试，121 个通过、0 失败、0 错误，1 个 POSIX 权限测试在 Windows 跳过。
Windows JDAVE 原生库测试通过，生成了新的 shaded JAR 和 JSON/XML SBOM。
本次新增 11 个回归测试。完整日志位于 `target/audit-verify.log`。

构建仍有发布材料告警：nanojson 和 youtube-source 的部分 Maven 许可证信息缺失、
GNU 许可证页面返回 403，SBOM 插件也报告 youtube-source 的仓库元数据读取告警。
构建成功不代表这些发布材料已经齐全；发布前需补齐并复核。

以上媒体测试没有连接 Discord，也没有验证真实频道中的可听性、DAVE 握手、长时间播放或断线恢复。不能将本地解码成功等同于完成上线验收。
